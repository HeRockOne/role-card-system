# 角色建模系统 Role Card System

职场沟通 / 向上管理建模的方法论 + 落地工具。

用「宗门」隐喻把职场关系建模成可维护的卡片体系：**总卡（宗门共性）→ 分卡（长老职能）→ 实例卡（个人打法）**，三层继承、子层覆盖父层，一套十维框架统一描述所有的上下级相处模式。

## 项目文件

| 文件 | 作用 |
|---|---|
| `宗门角色卡_长老与宗主维度体系.md` | 十维框架理论母本：身份档案 / 权杖边界 / 使命与账本 / 风格引擎 / 资源网络 / 恐惧清单 / 晋升算法 / 忠诚合约 / 时间配置 / 决策风格 |
| `角色卡合并与映射规范.md` | 三层继承规范 + 四条铁律（共性上升 / 差异下沉 / 互斥分叉 / 补丁隔离） |
| `快速反应系统_角色建模与中译中.md` | 三行卡「能 / 要 / 怕」快速建模法 + 宗门频道参数（向上沟通用语） |
| `角色卡系统_v1.html` | 网页工具：卡片增删改查 + 搜索 + 🌳继承链树视图 + 十维人话翻译 + 继承预告 + JSON 导出/导入，localStorage 持久化 |

## 快速开始

零依赖单文件，双击 `角色卡系统_v1.html` 即用（建议 Chrome / Edge）。数据保存在浏览器 localStorage，可随时导出 JSON 备份。

## 核心建模思路

1. **十维框架**：每一维都是一句人话问题，例如「权杖边界」= 你管什么、不越谁的线；「恐惧清单」= 上司最怕出什么乱子。
2. **三层继承**：总卡写宗门人人通用的共性 → 分卡写某一职能长老的职责差异 → 实例卡只写某个具体人的补丁差异。改一层，下游全部自动获得。
3. **编辑即建模**：新建/编辑实例卡时，每个维度实时显示「✏️ 本卡已在此定义(将覆盖父层) / 🌳 继承自 [来源] / 🈳 未定义」，照着继承预告填差异即可，不用背任何框架。

## 技术说明

- 解析引擎：`resolveCard` 沿 `parentId` 链合并（子覆盖父），`sourceOf` 溯源每个维度的显式定义来源，`chainOf` 输出根→叶链路。
- 数据模型：总卡/分卡存 `dims`，实例卡只存 `patches`（差异补丁，清空=撤销覆盖）。
