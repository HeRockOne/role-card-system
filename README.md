# 角色建模系统 Role Card System

职场沟通 / 向上管理建模的方法论 + 落地工具。

用「角色卡」把职场关系建模成可维护的卡片体系：**总卡（公司级共性）→ 分卡（部门职能）→ 实例卡（个人打法）**，三层继承、子层覆盖父层，一套十维框架统一描述所有的上下级相处模式。

## 快速开始

零依赖单文件，双击 `角色卡系统_v1.html` 即用（建议 Chrome / Edge，手机浏览器同样可用）。数据保存在浏览器 IndexedDB（容量比 localStorage 大得多，旧版本 localStorage 数据首次打开自动迁移），可随时导出 JSON 备份。

## v1.3 更新（2025）

- **层级流转链**：不再分 tab 跳来跳去。点卡片 = 向下钻（看它的下下级），顶栏面包屑每一环可点 = 向上回任意一层，上下流转闭环；每张卡标注父卡，可一键上钻。
- **浅色主题 + 夜间模式**：默认浅色护眼，右上角 🌙 一键切换深色，跟随系统偏好。
- **移动端适配**：手机单列布局，弹窗/抽屉全屏化，触控目标放大，竖屏横屏都可用。
- **IndexedDB 存储**：突破 localStorage 5MB 上限，数据量大、图片级内容也不怕；存储不可用时自动降级并提示。

## 核心建模思路

1. **十维框架**：每一维都是一句人话问题，例如「权杖边界」= 你管什么、不越谁的线；「恐惧清单」= 上司最怕出什么乱子。
2. **三层继承**：总卡写公司人人通用的共性 → 分卡写某一部门总监的职责差异 → 实例卡只写某个具体人的补丁差异。改一层，下游全部自动获得。
3. **编辑即建模**：新建/编辑实例卡时，每个维度实时显示「✏️ 本卡已在此定义(将覆盖父层) / 🌳 继承自 [来源] / 🈳 未定义」，照着继承预告填差异即可，不用背任何框架。

## 技术说明

- 解析引擎：`resolveCard` 沿 `parentId` 链合并（子覆盖父），`sourceOf` 溯源每个维度的显式定义来源，`chainOf` 输出根→叶链路。
- 数据模型：总卡/分卡存 `dims`，实例卡只存 `patches`（差异补丁，清空=撤销覆盖）。
- 存储层：IndexedDB（库 `rcs-db`，键 `rcs_cards_v13`）优先，不可用自动降级 localStorage；启动时自动迁移旧版 `rcs_v1` 数据。
